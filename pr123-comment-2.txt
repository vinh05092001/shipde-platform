### Detailed Findings & Required Changes

#### Finding 1 (Blocking): OpenAPI Contract Drift between YAML source and generated TS
- **Location:** `packages/contracts/src/openapi.ts:410-427` vs `docs/product-spec/contracts/openapi.yaml`
- **Issue:** The author directly modified `packages/contracts/src/openapi.ts` by adding `/admin/shops`, `AdminCreateShopRequest`, `AdminShopResponse`, and related operations, but did NOT update the source contract `docs/product-spec/contracts/openapi.yaml`.
- **Consequence:** `pnpm contract:check` fails with contract drift error. `AGENTS.md` establishes single-source contract gates.
- **Remediation:** Add the `/admin/shops` endpoints and schemas to `docs/product-spec/contracts/openapi.yaml`, then generate `packages/contracts/src/openapi.ts` via `pnpm contract:generate` and verify `pnpm contract:check` passes.

#### Finding 2 (Blocking): PR Body Contract Validation Failure (Placeholder Left Unreplaced)
- **Location:** PR #123 description (`## Codex review`)
- **Issue:** Under `## Codex review`, line 73 is left as `- Verdict: <PASS/CHANGES_REQUIRED/BLOCKED — filled by Codex>`.
- **Consequence:** `validate_pr_contract.py` regex `r"<[^>\n]+>"` detects unresolved template placeholders and fails the check.
- **Remediation:** Update the PR body to remove the `<...>` placeholder (e.g., `- Verdict: pending Codex review` or `- Verdict: CHANGES_REQUIRED`).

#### Finding 3 (Blocking): Windows Incompatibility in `package.json` & Missing Integration in `apps/api/package.json`
- **Location:** `package.json:44` and `apps/api/package.json:12`
- **Issue:**
  1. In `package.json:44`, `"test:admin"` was added as:
     `"test:admin": "PLATFORM_ADMIN_KEY=test-admin-key-2026 tsx apps/api/src/auth/admin-auth.supertest.spec.ts"`
     On Windows, inline POSIX environment variable definitions are not supported by `cmd.exe`, causing `pnpm run test:admin` to fail with `'PLATFORM_ADMIN_KEY' is not recognized as an internal or external command`.
     Notice `admin-auth.supertest.spec.ts:53` already sets `process.env.PLATFORM_ADMIN_KEY = VALID_ADMIN_KEY;` internally, so the inline variable is redundant.
  2. In `apps/api/package.json:12`, `"test"` only invokes `api.test.ts`, `api.supertest.spec.ts`, and `auth.supertest.spec.ts`. It does not include `admin-auth.supertest.spec.ts`. Therefore, standard monorepo CI / `pnpm --filter @shipde/api test` does not execute the new admin-auth test suite.
- **Remediation:** Update `package.json:44` to run cross-platform without inline env syntax (e.g., `tsx --tsconfig apps/api/tsconfig.json apps/api/src/auth/admin-auth.supertest.spec.ts`), and update `apps/api/package.json` line 12 to run `admin-auth.supertest.spec.ts` with `--tsconfig tsconfig.json`.

#### Finding 4 (Blocking): Missing 255 Character Upper Bound on `merchant_name` (BR-ADMIN-02)
- **Location:** `apps/api/src/auth/admin-auth.service.ts:39-45`
- **Issue:** Specification rule BR-ADMIN-02 mandates:
  > `merchant_name` required, 2-255 characters.
  The service only validates `dto.merchant_name.trim().length < 2`. It does not check `dto.merchant_name.trim().length > 255`.
- **Consequence:** An input with > 255 characters reaches Prisma where `Merchant.name` is `@db.VarChar(255)`, triggering an unhandled database exception (P2000) resulting in an unhandled 500 error instead of a canonical 400 `VALIDATION_ERROR`.
- **Remediation:** Add `dto.merchant_name.trim().length > 255` check in `createShop()` returning `VALIDATION_ERROR`.
