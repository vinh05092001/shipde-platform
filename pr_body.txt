## Implementation

New:
- `tools/ai-brain/sources.json` + `sources.js` - every dashboard source
  classified as model-source, router, agent-cli, harness, orchestrator or
  decision-service, with a dispatch table mapping a registry provider to a
  harness, a provider name and a model prefix. Adding a source is a row.
- `tools/ai-brain/harness.js` - Paseo and Cline adapters (`launch`, `resume`,
  `stop`, session id). The retired AO name throws. On Windows the npm `.cmd`
  shim is unwrapped to its real entry point, so `shell: false` holds and a
  prompt containing `&&` or `$(?)` still reaches the agent as text.
- `tools/ai-brain/decisions.js` - append-only JSONL: work item, candidates,
  rejected offerings with reasons, chosen offering, harness, session, outcome.
  Credentials are scrubbed at every depth. `closeWriter` releases a claim.
  `readDecisionsSafe` exported for callers that must refuse on a damaged log
  (missing directory = empty history; broken middle line = damage).

Changed:
- `executor.js` - launches through the adapter the registry chooses, and
  resumes an open writer instead of starting a second one.
- `scheduler.js` - `resourceCeiling`; measured free memory lowers the
  implementation ceiling, only when the caller asks to be measured.
- `ceiling.js` - two refusal shapes this machine actually produces.
- `cli.js dispatch` - `--cwd`, `--base`, `--decision-dir`, `--free-mb`,
  `--per-agent-mb`, `--governed-decision`, `--close` / `--fail|--complete`.
- `apps/web/src/context/AuthContext.tsx` - `isHydrating: boolean` state starts
  `true`, resolves to `false` in the `useEffect` `finally` block after the
  localStorage restore attempt. Exported via `AuthContextType`.
- `apps/web/src/app/page.tsx` - returns `null` during the single hydration tick
  (satisfies BRAIN.md rule 4: the screen must never stay in a loading frame when
  the user is not signed in). All six auth UI states are covered: loading
  (`null` during hydration), empty (unauthenticated with no error → login form),
  validation-error (inline field errors), error (server/network message),
  forbidden (`AuthStatusBlock` 403), and success (dashboard renders).

No API route, job or migration changed. The dashboard auth gate and its six UI
states are explicitly authorised in the Work Item's `Allowed paths` table.

## Safety and recovery

- One writer per work item and per branch, inside a plan and across restarts.
  The decision log, not the process table, is the evidence of a claim.
- A resumed session is told not to repeat an action with an external effect
  before checking whether it already happened.
- A harness with no `resume` cannot take over an open writer; that assignment
  is refused rather than restarted.
- `closeWriter` releases a claim when a session is stopped or dies, so a work
  item cannot be orphaned for ever.
- Free memory only lowers the ceiling. Spare RAM is never authorisation to
  exceed what a human agreed to.
- No credential is read, copied or logged. Credential presence is reported as
  present, absent, or unknown when it lives somewhere this cannot observe.

## Risks and limitations

- Hermes Agent has a registry entry and a dispatch row and is **not installed** on this host. Nothing dispatches to it yet.
- Jev is registered as a decision service with a confidence floor; `.worktrees/logs/jev.py` already uses it for lane selection, and moving that into `tools/ai-brain` is separate work.
- Cline has no resume, so an interrupted Cline writer must be released by hand.
- 350 MB per agent is measured from Cline and matched by the live Paseo run; a session running Codex or Claude may cost more, and nothing measures a live session yet.
- A refusal with no consumption reading cools the offering but adds no ledger entry, so it teaches no ceiling. That is existing behaviour, unchanged here.
- The decision log is local to this host; a second machine dispatching the same register would not see its writers.
- A `403 not licensed` (Copilot) is correctly not a quota refusal, and nothing yet cools a source that is unavailable for a non-quota reason.
